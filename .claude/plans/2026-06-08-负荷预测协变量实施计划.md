# 负荷预测协变量实施计划

> **执行要求：** 实施时使用测试驱动开发，按任务逐项完成并验证。推荐使用 `subagent-driven-development` 或 `executing-plans` 技能执行。

**目标：** 在现有 15 分钟 LightGBM 负荷预测模型中增加公共日历特征、可选工厂运营特征及可选天气协变量，降低负荷峰值低估误差，提高 MPC 储能削峰效果。

**总体架构：**

- 保留现有历史负荷滞后、滚动统计和日历特征。
- 新增统一的协变量模块，负责公共节假日、工厂运营日历、温度、湿度等数据的读取和时间对齐。
- 训练、递归预测、回测和 MPC 使用同一套协变量字段和顺序。
- 训练可以使用历史实际天气；MPC 和滚动回测只能使用决策时刻能够获得的未来天气预报，禁止使用未来实际天气。

**技术栈：** Python、pandas、NumPy、LightGBM、openpyxl、PyYAML、pytest。

## 二、实施前需要的数据

最终完成天气增强模型训练和验收，需要：

```text
1. 历史天气数据
   时间、温度，以及可选的湿度
   时间范围需要覆盖模型训练数据

2. 未来天气预报数据
   时间、预测温度，以及可选的预测湿度
   时间范围需要覆盖 MPC 的未来预测窗口

3. 公共节假日日历
   日期、日期类型
   需要包含法定节假日；不要求包含工厂调休或实际生产安排

4. 工厂运营日历，可选
   日期、工厂当天是否实际生产、是否加班、是否停产检修
   只有工厂能准确提供，不从公共日历推断
```

建议节假日文件格式：

```text
date          day_type
2026-10-01    holiday
```

其中：

```text
holiday = 法定节假日
normal  = 普通日期，可省略
```

可选工厂运营日历格式：

```text
date          is_factory_workday   is_factory_overtime   is_factory_shutdown
2026-10-10    1                    1                     0
2026-10-03    0                    0                     1
```

在天气文件尚未提供时，可以先完成代码接口、节假日特征和自动化测试；但无法证明天气特征是否真正改善预测效果。

```python
    """提取某次 MPC 未来预测窗口对应的协变量。"""
```

### 规则

```text
1. is_weekend 由自然日期自动生成，当前已有。
2. is_public_holiday 由公共节假日表生成。
3. is_day_before_holiday 和 is_day_after_holiday 基于公共节假日表生成。
4. is_factory_workday、is_factory_overtime、is_factory_shutdown 只在工厂运营日历提供时生成。
5. 不能用公共日历推断工厂实际生产状态。
6. 温度和湿度可以从小时级线性插值到 15 分钟级。
7. 只能在天气数据已有时间范围内插值。
8. 如果未来预测窗口缺少必要天气数据，必须明确报错。
9. 禁止用 0 静默填充缺失天气。
10. 禁止用未来实际天气替代预测天气。
```

### 测试

- 法定节假日识别正确。
- 节假日前一天、节假日后一天识别正确。
- 工厂运营日历缺失时，不生成或不启用工厂实际生产特征。
- 工厂运营日历提供时，`is_factory_workday` 等字段按外部输入读取。
- 小时温度能正确插值为 15 分钟温度。
- 未来天气缺失时明确报错。

```yaml

  external_columns:
    - is_public_holiday
    - is_day_before_holiday
    - is_day_after_holiday
```

### 训练流程

```text
1. 读取负荷训练时间线。
2. 生成公共节假日、节前和节后特征。
3. 将历史天气对齐到 15 分钟。
4. 合并协变量并训练增强模型。
5. 在滚动回测的每个未来窗口中传入对应协变量。
6. 输出特征重要性和峰值相关误差指标。
```

### 缺失数据处理

```text
节假日日历缺失：
  可以退化为普通星期和周末判断，并输出提示。

工厂运营日历缺失：
  不启用 is_factory_workday、is_factory_overtime、is_factory_shutdown。
  不能用周末或法定节假日替代工厂实际生产状态。

启用了天气特征但历史天气文件缺失：
  停止训练并明确报错。

禁止：
  将缺失天气全部填成 0 后继续训练。
```

### 示例 MPC 配置

```yaml
forecast_covariates:
  holiday_calendar_file: scenarios/china_public_holiday_calendar.xlsx
  holiday_calendar_sheet: calendar
  future_weather_file: scenarios/hehong_weather_forecast.xlsx
  future_weather_sheet: weather
```

### MPC 每步运行逻辑

```text
1. 当前 MPC 决策时刻为 t。
2. 生成未来 H=192 步，即未来 48 小时的时间线。
3. 提取未来 48 小时公共节假日、可选工厂运营日历和天气预报协变量。
4. 将 future_covariates 传给 LightGBM。
5. LightGBM 每预测一个未来 15 分钟点，都使用对应协变量。
6. 缺少必要未来天气时，在进入求解器前明确报错。
```

调用形式：

```python
fc_r = forecaster.predict(
    hist,
    st,
    end - t,
    future_covariates=future_covariates,
)
```

`file`、`naive96`、`naive672` 模式保持不变。

### 重要约束

历史回放仿真中，未来天气文件应代表天气预报数据。如果直接使用未来实际天气，得到的是理想化上限，不能当作真实上线效果。

## 十、任务七：基础模型与增强模型对比验收

**文件：**

```text
修改 microgrid/forecaster.py
新增 docs/load_forecast_covariates.md
```

### 输出 Excel

生成预测对比工作簿，包含：

```text
model_summary
  基础模型和增强模型总体指标

horizon_metrics
  0-6h、6-12h、12-24h、24-36h、36-48h 分段误差

peak_metrics
  P80/P90 低估误差、最大低估、实际峰值误差、高负荷时段 MAE

forecast_samples
  时间、实际负荷、基础预测、增强预测、两者误差
```

### 预测模型验收标准

```text
1. 增强模型总体 MAE 不得恶化超过 5%。
2. 增强模型应降低正向低估误差 P90 或实际峰值误差。
3. 特征重要性中至少有一个新增协变量产生贡献。
```

### MPC 对比验收

先分别运行 7 天：

```text
A：当前基础预测模型
B：公共日历和天气增强预测模型
```

重点比较：

```text
MPC 最终电网峰值
实际峰值点预测误差
功率层追加放电次数和幅度
储能 SOC 轨迹
是否产生异常充电峰
总可控成本
```

验收标准：

```text
1. 增强模型不能制造更高的异常充电峰。
2. 增强模型应降低或至少保持 MPC 电网峰值。
3. 增强模型应减少功率层实时纠偏的次数或幅度。
```
